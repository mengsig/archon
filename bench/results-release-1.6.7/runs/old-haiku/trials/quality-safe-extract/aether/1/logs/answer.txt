`safe_extract.py` is implemented and the test suite is extended; all 29 tests pass. The work is committed as `eb7a9ef` on `main`, with the identity already configured in the repo (mengsig).

**What changed**
- `safe_extract.py`: `extract(entries, root)` checks the whole batch before the first `mkdir` or write. It covers the batch type, root (existing real directory, not a symlink), entry shape, names, duplicates, file/directory collisions in either order, and every existing path component on disk. Symlinks, including dangling ones, are rejected and never followed. Files are written with exclusive-create (`"xb"`), so an existing file is never overwritten. Only missing-path lookups are treated as "absent"; any other OS error propagates.
- `test_safe_extract.py`: the two original tests are unchanged. I added 27 tests covering each rejection path, the no-partial-write guarantee, symlink cases, literal `%` and `..`-prefixed names, exact bytes including empty files, input-order return, and I/O error propagation.

**Choices I made where the spec was silent**
- Entries must be actual 2-tuples, so a `["name", data]` list is rejected as malformed.
- Data must be exactly `bytes`; `bytearray` and `memoryview` are rejected.
- Names must encode as UTF-8, so lone surrogates are rejected.
- An empty-string root is rejected rather than treated as the current directory.

**Gaps to know about**
- On case-insensitive filesystems, a batch with case-only collisions (`A` and `a`) passes validation. The second write then fails with `FileExistsError` after earlier files are already created. The spec does not say how to handle this, so I left it as is.
- Per the spec, there is no rollback after an I/O error during writing.
