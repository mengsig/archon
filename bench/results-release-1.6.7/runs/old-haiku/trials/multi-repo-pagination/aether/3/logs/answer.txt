**API behaviour**
- `limit` accepts 1–3 ASCII digits in range 1–100. Anything else, including `"0"`, `"101"`, `"1.5"`, `""`, `"x"` and oversized digit strings, returns 400 `{"error": ...}`.
- `cursor` is a base64url-encoded id, so clients treat it as opaque. Each page returns items with `id` greater than the cursor's id, so the cursor keeps pointing at the same place even if items are added later. Malformed cursors return 400.
- `next_cursor` is `null` when no items remain after the page.

**Client behaviour**
- `listItems` sends no cursor on the first request and passes each `next_cursor` back unchanged until it is `null` or absent.
- It throws if a page has no `items` array, a cursor is not a string, or a cursor repeats. Without the repeat check, a misbehaving server could make it loop forever.
- It does not send `limit`, so the server default of 20 applies and 57 items take three requests.
