I implemented `ledger.py` to the spec and committed it as `4f360f9` on `main`. The 22 unit tests pass with `python3 -m unittest test_ledger`.

- **Concurrency:** each ledger has one `threading.Lock` that every transfer and snapshot takes. That makes operations linearizable, and since there is only one lock, opposite transfers cannot deadlock.
- **Construction:** balances and amounts must be built-in ints (booleans rejected) in `[0, MAX_BALANCE]` and `[1, MAX_BALANCE]` respectively. Account names must be nonempty strings. The input dict is copied, and snapshots return copies.
- **Transfers:** the amount is validated before any account lookup. Unknown or non-string account names raise `KeyError`. Insufficient funds and destination overflow return `False` with no change. Same-account transfers return whether the balance covers the amount and never modify it.
- **Tests:** cover validation, boundary values, copy isolation, same-account cases, and two thread tests (opposite transfers, and snapshots never seeing a half-finished transfer). The thread tests use fixed round counts, with no randomness or timing.
