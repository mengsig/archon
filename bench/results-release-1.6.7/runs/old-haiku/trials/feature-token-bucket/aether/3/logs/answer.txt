The rate limiter is implemented in `ratelimit.py` and committed as `4fb82fd` on `main`. All 20 unit tests pass: the 3 original tests plus 17 new ones.

I made two choices beyond the literal spec, and you may want to review them:

1. **Float tolerance (1e-9 tokens).** Without it, `wait_time()` could return a time after which `try_acquire()` still failed by about 3e-16. A randomized check reproduced this in roughly 99% of multi-step trials. With the tolerance, the same check shows 0 failures in 20,000 trials. The balance is also clamped at zero after an acquire, so the tolerance can't leave a tiny negative balance.
2. **Stricter validation.** Infinite `capacity` or `refill_per_sec` is rejected, since the spec only covers `<= 0`. `max_keys` must be an int of at least 1, because a float would break the eviction bound. Invalid `n` is checked before a key is created or touched, so a bad call can't evict another key.
