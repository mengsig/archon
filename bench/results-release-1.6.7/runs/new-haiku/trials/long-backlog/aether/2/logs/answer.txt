| Ticket | Commit | Change |
|---|---|---|
| TT-101 | `45186bc` | `parse_due` raises `InvalidDate` (a `ValueError` subclass) for impossible dates, unsupported forms and out-of-range offsets. It no longer clamps. |
| TT-102 | `c232eaa` | `to_csv` uses the `csv` module with CRLF line endings, so commas, quotes and newlines are quoted per RFC 4180. |
| TT-103 | `66662fa` | `search` parses a small query language: quoted phrases, AND-ed terms, `tag:NAME`, `status:open|done`. Bad fields, unknown statuses and unterminated quotes raise `QueryError`. |

Each ticket has its own test file: `tests/test_dates.py`, `tests/test_export.py`, `tests/test_search.py`, `tests/test_undo.py`.

Judgment calls within the ticket text:
- **TT-101:** offsets too large for a date (e.g. `+99999999999d`) also raise `InvalidDate`. Digits match `[0-9]` rather than `\d`, so Unicode digits are rejected.
- **TT-103:** quoted text is always literal, so `"Re: notes"` matches the title instead of being read as a field. Field names and status values are case-insensitive. `tag:` with an empty value raises `QueryError`. An empty phrase `""` matches every task.
- **TT-104:** `complete` records the previous status. Completing an already-done task and then undoing it leaves the task done; a second undo reopens it. `delete` stores a copy taken at deletion time, so the restored task has equal fields but is a new object, not the original instance. `undo()` returns `None`.
