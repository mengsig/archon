I implemented `ledger.py` against `SPEC.md`, added focused tests, and committed both as `559b698` on `main`, authored as `mengsig`. All 22 tests pass across repeated runs with `python3 -m unittest test_ledger`.

- **Construction:** accepts only a dict with nonempty string names and exact-`int` balances in `[0, MAX_BALANCE]`. Booleans, floats and non-dict inputs raise `ValueError`. The input is copied.
- **`transfer`:** validates the amount before looking up accounts, then raises `KeyError` for an unknown account. Insufficient funds or destination overflow return `False` and change nothing. Same-account transfers return `True` iff funds suffice and never change the balance, including at `MAX_BALANCE`.
- **`snapshot`:** returns a copy.
- **Thread safety:** one `threading.Lock` per ledger makes every operation atomic. With no nested locks, opposite transfers cannot deadlock.

One choice to review: an unhashable account name such as a list raises `TypeError` from the dict lookup, not `KeyError`. The spec doesn't cover that case, so I left it.

The concurrency tests use thread joins with a 60-second timeout only to detect hangs.
