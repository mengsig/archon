I implemented `ledger.py` to the spec and expanded `test_ledger.py`. The work is committed as `ce9d71e` on `main`, authored as `mengsig`. All 27 tests pass with `python3 -m unittest`.

- **Locking:** each ledger has one `threading.Lock` around `transfer` and `snapshot`. Snapshots never see a half-applied transfer, and opposite transfers cannot deadlock because there is only one lock.
- **Construction:** the input dict is copied, then the copy is validated. Names must be nonempty strings. Balances must be plain `int` (bools are rejected) in `[0, MAX_BALANCE]`. Non-dict input raises `ValueError`.
- **Transfers:** the amount is validated before any account lookup. Unknown or non-string account names raise `KeyError`. Insufficient funds or destination overflow return `False` with no writes.
- **Self-transfers:** these return `True` iff the balance covers the amount, and never change it, even at `MAX_BALANCE`.
- **Snapshots:** each call returns a fresh copy.

The concurrency tests use `join(timeout=60)` as a deadlock guard. That is a timeout, not a timing measurement, but it is a wall-clock value, so say if you want it removed.
