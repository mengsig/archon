Refactored the orders crate so Order::status is an OrderStatus enum. Committed as b79a69b on main (git user mengsig, no attribution line). cargo test passes: 5 tests (the 3 original plus 2 new ones for parsing/display and the transition table).

What changed:
- src/status.rs (new): OrderStatus { Pending, Paid, Shipped, Cancelled } deriving Debug, Clone, Copy, PartialEq, Eq, Hash. Provides as_str(), Display (same lowercase text), FromStr with Err = ParseStatusError, and can_transition_to() encoding pending->paid, pending->cancelled, paid->shipped, paid->cancelled. ParseStatusError implements Error and its message is `unknown status "<input>"`.
- lib.rs re-exports OrderStatus and ParseStatusError from the crate root.
- order.rs, billing.rs, shipping.rs: pay/ship/cancel now check can_transition_to, so their error messages are unchanged. is_open, outstanding_cents and ready_to_ship compare enum variants.
- report.rs: from_line uses FromStr and passes its error message through, so the CSV error text is unchanged.
- The status string literals now appear only in src/status.rs (checked by grep over src/).

Decisions to review:
- report::status_counts now returns Vec<(OrderStatus, usize)> instead of Vec<(String, usize)>. This is a public signature change. Output order is still sorted by the lowercase name, not by enum declaration order, so the output matches the old code.
- tests/orders.rs still contains the expected error-message strings such as "order 2 cannot be shipped: it is pending". These are the observable output being asserted, so I kept them as literals.
- I did not add asserts to the functions. The existing code had none, and adding them would change behaviour (panic instead of Err), so I left that out of scope.
