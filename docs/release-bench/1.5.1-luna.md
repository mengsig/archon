# Release 1.5.1: Luna post-release check

**Verdict: no decrease (report only).** Archon v1.5.1 on the published Aether
1.3.1 passed 8/8 Archon trials on `codex/gpt-6-luna` over two runs. v1.5.0 on
the published Aether 1.3.0 passed 7/8. Cost per run moved +0.6% and wall time
per run +0.1%, both far inside the noise of two runs. Both v1.5.1 runs passed
the stored Luna baseline (`baseline-luna.json`, 4/4). The v1.5.0 run 2 failed
it on one miss.

The Haiku gate passed before the release (see `bench/results-release-1.5.1`).
This Luna check was deferred until the Codex quota reset and gates nothing.

| Arm | Runs | Archon trials passed | Cost/run * | Cost/trial * | Wall/run | Wall/trial |
|---|---|---|---|---|---|---|
| v1.5.0, Aether 1.3.0 | 2 | 7/8 | $0.0576 | $0.0144 | 584 s | 146 s |
| v1.5.1, Aether 1.3.1 | 2 | 8/8 | $0.0579 (+0.6%) | $0.0145 | 584 s (+0.1%) | 146 s |

- `*` Luna costs are Aether's estimates (Codex usage is unbilled). Eight of
  the sixteen Archon trials include a part Aether reported as incomplete
  (`cost_gap` `mixed`), on both arms, so the costs are not exact.
- Mean per-run figures are the average of the two runs below.
- The Aether (single-agent) arm is the comparison arm, not the gate: 7/8 on
  Aether 1.3.0 and 6/8 on Aether 1.3.1. Its misses were `review-seeded-bug`
  on 1.3.1 twice (rubric score 0.5, both runs, with otherwise sound answers)
  and `quality-retry-budget` on 1.3.0 once. Two runs cannot separate this
  from rubric noise; it is a thing to watch if Aether's Luna check shows it.
  It does not affect Archon's verdict.

## Method

The method is the documented smoke gate (`bench/README.md`, `bench/results-smoke/README.md`),
Luna arm: `archon-bench smoke --model codex/gpt-6-luna --effort medium
--baseline bench/results-smoke/baseline-luna.json`.

- One trial per task and arm (`archon`, `aether`), four tasks, medium effort,
  run serially under the default $7 cap. The model, effort and tasks match
  the stored Luna baseline.
- **Assets.** Archon v1.5.1 and v1.5.0 are the published
  `x86_64-unknown-linux-musl` release archives, each checked with
  `sha256sum -c SHA256SUMS` before use, reporting `archon 1.5.1` and `archon
  1.5.0`. The Aether arms are the published `aether-x86_64-unknown-linux-musl`
  archives, also checked against `SHA256SUMS`: v1.3.1 (new arm) and v1.3.0
  (old arm, the Aether v1.5.0 shipped with, as in the Haiku gate). The old
  archond refuses the newer Aether's conversation path, so each Archon runs
  on the Aether it released with.
- **Bench binary.** Both arms were measured by one `archon-bench`, built with
  `cargo build --release --locked -p archon-bench` from commit `4f8da5f5`
  (`next`). `bench/` is unchanged since the `v1.5.1` tag.
- **Slot and load.** The run waited for the host's 5-minute load average to
  drop below 8 (it was 7.6), then queued in the host CI slot
  (`scripts/ci-slot.sh`) behind the Aether Luna check (`make bench-release
  ARMS=luna`), and ran under `nice -n 10`. The runs started at 1-minute
  loads of 7.2, 7.0, 8.7 and 5.7.
- **Sandbox.** Each run had a new private directory under
  `~/.local/share/archon-bench/` with its own aetherd, Archon and Aether
  config and data, sockets, `TMPDIR` and a private `HOME`, all started
  through an `env -i` wrapper. The `HOME` held a mode-600 copy of the Codex
  credentials (deleted after each run) and an `archon-bench` git identity.
  Each aetherd was stopped by its socket. No operator daemon, configuration
  or data was used.
- **Order.** v1.5.0, v1.5.1, v1.5.0, v1.5.1.
- **Not done.** The SWE family was not run. No third run was made to
  confirm or reject the single v1.5.0 miss.
