Refactored the `orders` crate's order status from `String` to an `OrderStatus` enum and committed it as 1f31b8f ("Replace string order status with OrderStatus enum") on main. `cargo test` passes: 3 unit tests in status.rs, 3 integration tests, 0 failures. `cargo clippy --all-targets` is clean.

What changed:
- src/status.rs (new): `OrderStatus` (Pending, Paid, Shipped, Cancelled; derives Debug, Clone, Copy, PartialEq, Eq, Hash), `as_str`, `Display` (uses `f.pad`, so width handling matches the old String output), `can_transition_to`, `FromStr` with `ParseStatusError`. The error implements std::error::Error and its message is `unknown status "<input>"`. The status literals appear only in this file.
- `Order::status` is now `OrderStatus`. `pay`, `ship` and `cancel` check `can_transition_to`, so the lifecycle is encoded in one place. Error messages are unchanged.
- `report::from_line` keeps its old error text and check order. `status_counts` returns `Vec<(OrderStatus, usize)>`, sorted by lowercase name. A derived Ord would sort by declaration order, so the sort is explicit.
- The crate root re-exports `OrderStatus` and `ParseStatusError`.
- tests/orders.rs compares against the enum directly. The pinned CSV and error-message strings are kept as literals because they are the observable output.

Decisions and caveats:
- The one public API change is the return type of `report::status_counts`, now `(OrderStatus, usize)` instead of `(String, usize)`. Display output is identical. Callers that compared against strings will need updating.

- The baseline was already not rustfmt-clean (`cargo fmt --check` failed before my change). I did not reformat untouched code, so the existing long `format!` lines keep their original style.
