The root cause is stale cache invalidation in the merchant price update path:

- `listing()` caches a snapshot of each category page—including `priceCents`—under a `listing:<category>:<page>` key ([catalog.js](/home/mengsig/.local/share/archon-bench/release-167-R4V9TB/r-lzwaa8jj/archon-bench/work/20261128T072020Z/739ac8f65dacee4810b960bb/ask-cache-invalidation/src/catalog.js:22)).
- `updatePrice()` updates the store and deletes only `product:<sku>` ([pricing.js](/home/mengsig/.local/share/archon-bench/release-167-R4V9TB/r-lzwaa8jj/archon-bench/work/20261128T072020Z/739ac8f65dacee4810b960bb/ask-cache-invalidation/src/pricing.js:10)). The next product-page read therefore fetches the updated price, while category pages keep serving their cached snapshots.
- Listing entries expire after **600 seconds**, or ten minutes ([config.js](/home/mengsig/.local/share/archon-bench/release-167-R4V9TB/r-lzwaa8jj/archon-bench/work/20261128T072020Z/739ac8f65dacee4810b960bb/ask-cache-invalidation/src/config.js:7)). So a listing can remain stale for up to ten minutes from when it was cached; it refreshes on the next read after expiry ([cache.js](/home/mengsig/.local/share/archon-bench/release-167-R4V9TB/r-lzwaa8jj/archon-bench/work/20261128T072020Z/739ac8f65dacee4810b960bb/ask-cache-invalidation/src/cache.js:10)).

The fix is to invalidate the affected category’s listing cache entries when a price changes, across all pages that might contain the SKU. The update path can get the product’s category and delete those listing keys; alternatively, add category-level invalidation support, such as a category version key. Lowering the listing TTL would only shorten the stale window, not correct the missing invalidation. No code was changed.
