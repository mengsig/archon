The stale category prices come from the separate listing cache path in [catalog.js](/home/mengsig/.local/share/archon-bench/release-167-R4V9TB/r-lzwaa8jj/archon-bench/work/20261128T072020Z/b1c87aa1d23ec658b6131c8f/.archon/data/orchestrator/repos/ask-cache-invalidation/src/catalog.js). `listing()` caches a snapshot of each category page’s rows under a `listing:<category>:<page>` key.

When a merchant changes a price, [pricing.js](/home/mengsig/.local/share/archon-bench/release-167-R4V9TB/r-lzwaa8jj/archon-bench/work/20261128T072020Z/b1c87aa1d23ec658b6131c8f/.archon/data/orchestrator/repos/ask-cache-invalidation/src/pricing.js) updates the store and deletes only that product’s cache key. So `product()` reloads the new price immediately, while cached category rows remain untouched.

The listing TTL is 600 seconds in [config.js](/home/mengsig/.local/share/archon-bench/release-167-R4V9TB/r-lzwaa8jj/archon-bench/work/20261128T072020Z/b1c87aa1d23ec658b6131c8f/.archon/data/orchestrator/repos/ask-cache-invalidation/src/config.js). That means a listing can show the old price for up to ten minutes from when that page was cached; after expiration, the next request rebuilds it from the updated store.

The fix is to invalidate every cached page for the product’s category when its price changes. The current cache supports deleting a single key only ([cache.js](/home/mengsig/.local/share/archon-bench/release-167-R4V9TB/r-lzwaa8jj/archon-bench/work/20261128T072020Z/b1c87aa1d23ec658b6131c8f/.archon/data/orchestrator/repos/ask-cache-invalidation/src/cache.js)), so add a way to track or invalidate that category’s listing keys, or use a category version in listing keys.
