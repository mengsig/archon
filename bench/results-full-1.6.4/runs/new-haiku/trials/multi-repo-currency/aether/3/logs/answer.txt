Both repositories now handle currency, and each has a commit: `ledger` at `e122447` and `reports` at `1050c2c`. Both test suites pass: `cargo test` has 9 tests and `python3 -m unittest` has 5.

**ledger**
- Input lines take an optional fourth column, an ISO 4217 code of exactly three uppercase ASCII letters. It defaults to `USD` when missing.
- The output header is `date,account,amount_cents,currency`, and every row carries its currency.
- A malformed code prints `line N: ...` to stderr and exits 2. Other input errors still exit 1.

**reports**
- Totals are per account and currency, printed as `account,currency,total_cents`, sorted by account then currency.
- A CSV without a `currency` column counts as `USD`.
- A malformed code prints an error naming the line to stderr and exits 2.

I also updated both READMEs and checked the pipeline end to end: ledger output piped into reports gives the expected per-currency totals.

Choices I made:
- An empty fourth column, such as a trailing tab, is treated as a malformed code (exit 2), not as the `USD` default.
- The commits use the repo's configured git identity. I left out the Co-Authored-By line from the attribution reminder, because the project CLAUDE.md says not to mention Claude Code in commits.
- If ledger hits a bad line partway through, the header and earlier rows are already on stdout. That behaviour predates this change and I did not alter it.
