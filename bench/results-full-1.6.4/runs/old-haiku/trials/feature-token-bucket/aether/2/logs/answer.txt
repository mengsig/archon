**What's implemented:**
- **`TokenBucket`**: starts full, refills continuously and caps at capacity, and rejects `n <= 0` or `n > capacity`. `wait_time` consumes nothing.
- **Clock going backwards**: the bucket only advances its refill time when the clock passes the latest time it has seen, so backwards jumps add or remove nothing.
- **`KeyedLimiter`**: one bucket per key, kept in an `OrderedDict` for LRU order. Both `try_acquire` and `wait_time` count as a use, and an evicted key returns full.
- **Validation before side effects**: `n` is checked before a key is created, so an invalid call cannot evict another key.
- **Standard library only**: the module imports just `time` and `collections`.

**Choices I made that you may want to review:**
- Validation of `capacity`, `refill_per_sec` and `n` is shared by two small helpers, `_check_rates` and `_check_n`, so both classes enforce the same rules.
- Each class has two assertions on its internal invariants, which only fire on a bug and not on bad user input.

**Known limitation:** the refill uses floating-point arithmetic. In rare cases `wait_time(n)` may return a delay after which `try_acquire(n)` still fails by a rounding error. I did not add a tolerance because the spec doesn't mention one. Say if you want one.
