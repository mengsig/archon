`src/tokens.js` should not ship as written. The signature check in `verify()` is broken: it lets an attacker forge a token without the secret.

## Findings, most severe first

1. **Critical: `verify()`, line 27.** The check is `expected.startsWith(signature)`. That is a prefix match, not a full comparison, and it is not constant-time.
   - An empty signature is accepted. `verify(base64url('{"user":"root","exp":9e15}') + ".", SECRET)` returns the forged payload. The check on line 25 does not reject `""`.
   - Without the key, an attacker can recover the full MAC for any body they choose, one character at a time, using `verify()` as the oracle. In my run it took 1,331 calls, and the result matched the real HMAC of the forged body.
   - Fix: reject empty signatures and compare the full MAC with `crypto.timingSafeEqual` on equal-length buffers.

2. **High: `verify()`, lines 22–26.** The secret is not validated. `sign()` refuses secrets under 32 characters, but `verify()` accepts `""`, and a token MAC'd with an empty key is then accepted. If a missing environment variable leaves the verifying side with an empty secret, every token is forgeable.
   - Fix: apply the same secret validation in `verify()`.

3. **Medium: `verify()`, lines 28–29.** `JSON.parse` and `payload.exp` are unguarded. Malformed bodies throw `SyntaxError`, and a body that decodes to `null` throws `TypeError`. Callers that expect `null` on rejection will crash or return a 500.
   - Fix: return `null` for unparseable or non-object payloads.

4. **Low: `verify()`, line 24.** `split('.')` ignores extra segments, so `validToken + ".garbage"` verifies. Fix: require exactly two parts.

5. **Low: `verify()` line 29 and `sign()`.** A `NaN` `now` makes the expiry check always pass. `sign()` accepts zero or negative `ttlSeconds` and silently produces already-expired tokens. Fix: validate numeric inputs.

6. **Low: `sign()`, line 15.** The secret check is length-only, with no entropy requirement. `'k'.repeat(32)` passes.

7. **Design: no `typ`, `aud` or `kid` claims.** Tokens are not scoped to a purpose, and there is no way to rotate keys. Decide this before release.

## Test gaps

`node --test` passes 4/4, which is why the bypass went unnoticed. The tampered-payload test reuses the real signature, so it never exercises a truncated or empty one. Missing tests: empty and truncated signature, malformed payload, extra segments, and an empty secret passed to `verify`.

I did not change any code. The probe scripts ran from `/tmp` against the module, and the repo's `git status` is unchanged.
