The root cause is the **category listing cache path**. `Catalog.listing()` caches each category and page under `listing:<category>:<page>` for `LISTING_TTL_SECONDS`, which is 600 seconds (10 minutes), in [catalog.js](/home/mengsig/.local/share/archon-bench/f164-p9b3h69d/archon-bench/work/20261120T084439Z/7fe52022972619bceaa21fdb/.archon/data/orchestrator/repos/ask-cache-invalidation/src/catalog.js:22) and [config.js](/home/mengsig/.local/share/archon-bench/f164-p9b3h69d/archon-bench/work/20261120T084439Z/7fe52022972619bceaa21fdb/.archon/data/orchestrator/repos/ask-cache-invalidation/src/config.js:4).

`updatePrice()` updates the store and deletes only the individual product cache entry, as shown in [pricing.js](/home/mengsig/.local/share/archon-bench/f164-p9b3h69d/archon-bench/work/20261120T084439Z/7fe52022972619bceaa21fdb/.archon/data/orchestrator/repos/ask-cache-invalidation/src/pricing.js:6). So a product page reload fetches the new price immediately, while an already cached category listing keeps its old price until that listing entry expires.

The fix is to invalidate the affected category listing cache entries when a price changes—for every page of the product’s category—or use a category-level version/key scheme so a price update makes those cached listings unreachable. Lowering the TTL would only shorten the stale-price window; it would not remove the invalidation gap. No code was changed.
