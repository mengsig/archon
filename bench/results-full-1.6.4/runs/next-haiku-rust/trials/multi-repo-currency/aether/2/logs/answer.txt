Multi-currency support is implemented and committed in both repositories. Both suites pass: `cargo test` in ledger (8/8) and `python3 -m unittest` in reports (4/4). An end-to-end pipe from ledger into reports works.

ledger (commit dc0c596):
- Lines accept an optional 4th column, the currency. It defaults to USD when missing. Codes must be exactly three uppercase ASCII letters, and the value is trimmed like the other fields.
- The header is now `date,account,amount_cents,currency`, and every row carries its currency.
- Parse errors are a `LineError` enum. A bad currency exits 2 and other errors exit 1, both with `line N:` on stderr.
- Tests cover defaults, rejected codes, field counts, and the binary's exit codes and output.
- README updated.

reports (commit c3f213b):
- Totals are keyed by (account, currency). Output is `account,currency,total_cents`, sorted by account then currency.
- A CSV with no `currency` column counts as USD. A malformed code prints `error: line N: bad currency ...` to stderr and exits 2.
- Validation is strict (no trimming), since the input is machine-generated.
- Tests cover per-currency totals, legacy input, sort order, and the exit-2 path.
- README updated.

Choices and assumptions to review:
- I did not bump ledger's Cargo version (0.3.0). The output format changed, so a bump to 0.4.0 may be wanted.
- Commits carry no attribution trailer. The CLAUDE.md rule to not add attribution takes precedence over the Co-Authored-By reminder.
- I did not add the fixed assert count from CLAUDE.md to existing functions. I added one `debug_assert!` in `to_csv_row`, and the rest of the new validation is explicit error returns.
- `reports.py` still lets a non-numeric `amount_cents` raise a traceback (exit 1), as before. That is outside this change.
