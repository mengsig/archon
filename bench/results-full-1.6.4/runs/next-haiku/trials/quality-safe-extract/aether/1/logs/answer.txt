I implemented `extract(entries, root)` in `safe_extract.py` according to `SPEC.md` and added focused tests. The work is committed as `94575d8` on `main`, with no attribution lines, following the CLAUDE.md rule. All 41 tests pass with `python3 -m unittest -v test_safe_extract`.

**Behavior:** the whole batch is validated before any file is written. Validation covers:
- the batch must be a list, so tuples, generators and iterators are rejected without being consumed;
- the root must be a str or Path naming an existing real directory, not a symlink;
- each entry must be a 2-tuple with a str name and bytes data;
- names must be nonempty relative POSIX paths with no leading `/`, backslash, colon, NUL, or empty, `.` or `..` component;
- duplicates and file/directory collisions are rejected in either order;
- for each target, no existing component may be a symlink (dangling included), no ancestor may be a non-directory, and the target must be absent.

Writes use exclusive creation (`"xb"`), so an existing file is never overwritten. Results are returned in input order. Unexpected OSErrors propagate.

**Assumptions** where the spec was open:
- Entries must be tuples, so a `[name, data]` list is rejected.
- An empty-string root is rejected rather than treated as the current directory.
- Only str and Path roots are accepted.
- A name containing a lone surrogate is rejected as not valid Unicode.

**Other notes:**
- The permission-error test is skipped when running as root.
- I ran the tests in place and removed the resulting `__pycache__/` directory. The working tree is clean.
