`catalog-service` caches category listings in `Catalog.listing()` under keys like `listing:tools:0`, with a TTL set by `LISTING_TTL_SECONDS` in [config.js](/home/mengsig/.local/share/archon-bench/full-165-Q4J35ZNK/r-dwsb1bl5/archon-bench/work/20261125T011222Z/00d57eb0bf83ac12cfea652e/ask-cache-invalidation/src/config.js). Those cached rows include `priceCents`.

When a merchant changes a price, `updatePrice()` updates the store and deletes only the product cache entry (`product:<sku>`) in [pricing.js](/home/mengsig/.local/share/archon-bench/full-165-Q4J35ZNK/r-dwsb1bl5/archon-bench/work/20261125T011222Z/00d57eb0bf83ac12cfea652e/ask-cache-invalidation/src/pricing.js). So product pages reload the new price immediately, while already cached category listings remain stale until their TTL expires. The roughly ten-minute delay is the listing TTL; the precise configured value is in `config.js`.

The fix is to invalidate the affected category listing cache keys after a price update, across every page for that category. The update path can look up the product’s category and delete those keys, or the service can use a category version/generation in listing keys so a category update makes old entries unreachable. No code was changed.
