The `orders` crate now stores status as an `OrderStatus` enum. The work is committed as `56e0c9f` on `main`, and `cargo test` passes: 3 integration tests, plus 3 new unit tests in `status.rs`. Clippy with `-D warnings` is clean.

**What changed**
- `src/status.rs` is new. It holds the enum, `as_str`, `Display` (via `f.pad`, so width flags behave as they did on `String`), `FromStr`, `ParseStatusError`, and `can_transition_to`. The status literals appear only here.
- `pay`, `ship` and `cancel` now check `can_transition_to`. For the existing states this is the same condition as before, so the error messages are unchanged.
- `from_line` gets its "unknown status" text from `ParseStatusError`'s `Display`, which produces the same string as before. Field parse order is unchanged.
- `src/lib.rs` re-exports `OrderStatus` and `ParseStatusError` from the crate root.
- `tests/orders.rs` is untouched and still passes, so the existing observable behaviour is verified.

**Decisions to review**
- **Public API change:** `report::status_counts` now returns `Vec<(OrderStatus, usize)>` instead of `Vec<(String, usize)>`. Ordering is kept by sorting on `as_str()`, not on the enum's declaration order. The existing test still compiles because it calls `to_string()` on each entry.
