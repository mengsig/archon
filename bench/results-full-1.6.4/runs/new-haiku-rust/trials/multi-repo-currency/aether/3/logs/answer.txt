Both repos now handle currency. Each has a commit, and all tests pass (`cargo test`: 9 passed in `ledger`; `python3 -m unittest`: 5 passed in `reports`).

**`ledger` (commit `39bd55e`)**
- Lines take an optional fourth column. A missing column means `USD`.
- The header is `date,account,amount_cents,currency`, and every row carries its currency.
- A bad currency code exits 2 with `line N: bad currency "..."` on stderr. Other input errors still exit 1. I did this with a `ParseError` enum, so `main` can choose the status.
- Tests cover the default, explicit codes, rejected codes, and the binary's exit statuses.

**`reports` (commit `dd87633`)**
- Output is `account,currency,total_cents`, sorted by account, then currency.
- CSV without a `currency` column counts as `USD`.
- A bad code prints `error: line N: ...` to stderr and exits 2.
- Tests cover per-currency totals, the old format, the bad-code exit, and the header.

I also ran the pipeline end to end: ledger output piped into `reports.py` gives the expected per-currency totals.

**Choices I made, so you can redirect:**
- An empty fourth column (`...\t`) is treated as a malformed currency, exit 2, rather than as missing. The spec only covers the two cases of a missing column and a malformed code, so this is my reading.
- Currency codes are trimmed like the other fields, so `" EUR "` is accepted.
- I did not bump `ledger`'s version (0.3.0), even though the output format changed. That's a call for you.
- The commits have no `Co-Authored-By` trailer or "generated by" line. Your CLAUDE.md asks for no Claude attribution, which overrides the attribution reminder.
- Commits use the repo's configured git identity (`mengsig <marcus.engsig@tii.ae>`). If "my git user" should be a different identity, the commits need amending.

`cargo fmt --check` still reports formatting differences in `ledger/src/lib.rs`. They are in lines I didn't change, so I left them.
