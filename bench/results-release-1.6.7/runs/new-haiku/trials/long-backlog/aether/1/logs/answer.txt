Choices I made where the ticket was silent:
- **Undo of a double complete:** `complete` on an already-done task is recorded, and undo restores the previous status (done). The ticket's literal wording would make it open. Say if you want the literal behaviour.
- **Undo of delete:** the store keeps a copy taken at delete time, so later changes to the object returned by `delete()` don't leak into the restored task. Undo records refer to tasks by id, so a task restored by undo is the one later undos act on.
- **Search quoting:** quotes can appear anywhere in a term, so `tag:"work,urgent"` works. A colon inside quotes is plain text, so `"write: report"` is a phrase. A bare `10:30` raises `QueryError` as an unknown field; quote it to search for it.
- **Search edge cases:** field names and status values are case-insensitive. `tag:` with no value, and `status:` with no value, raise `QueryError`. An empty phrase `""` matches every task.
- **Date parsing:** I changed `\d` to `[0-9]` in the date regexes, so non-ASCII digits are rejected. Out-of-range offsets like `+99999999999d` raise `InvalidDate`, not `OverflowError`.
