The `OrderStatus` refactor is committed as `5df26f7` on `main`. `cargo test` passes (3 integration tests, 3 unit tests in `status.rs`, 0 doc-tests), and clippy reports no warnings.

**What changed**
- **`src/status.rs`** (new): the `OrderStatus` enum with `as_str`, `Display`, `can_transition_to`, and `FromStr`, plus the public `ParseStatusError`. The status strings now appear only in this file.
- **`Order::status`** is an `OrderStatus`. `pay`, `ship`, and `cancel` check `can_transition_to`, which allows exactly the moves the old string checks allowed.
- **`src/lib.rs`** re-exports `OrderStatus` and `ParseStatusError`.
- **`tests/orders.rs`** compares enum values instead of strings. I added unit tests in `status.rs` for the transition table, the parse round-trip, and the error message.

**Behaviour kept the same**
- Error texts for pay, ship, and cancel are unchanged.
- `from_line` still returns `unknown status "lost"` for a bad status name.
- The report sorts by status name (cancelled, paid, pending, shipped), not by enum declaration order.
