Implemented safe_extract.extract per SPEC.md and added focused tests. Committed as b5ba9a1 on main (author: repo-configured mengsig identity). All 34 tests pass via `python3 -m unittest test_safe_extract` (2 original, 32 new).

What the implementation does:
- Batch shape: entries must be a list (tuples, iterators, generators, None rejected without consuming them). Each entry must be a 2-tuple with str name and bytes data.
- Names: rejected if empty, absolute, contain backslash/colon/NUL, or have empty, '.', or '..' components. Names are not decoded, so '%' is literal. Names that cannot be encoded for the filesystem (lone surrogates) are rejected up front.
- Batch conflicts: duplicates and file/directory collisions are rejected in either order.
- Root: must be str or Path, non-empty, existing, a real directory and not a symlink. Converting through Path first makes a trailing-slash symlink ("link/") get rejected; a raw lstat on that string follows the link.
- Filesystem checks use lstat only. Ancestors must be real directories and not symlinks. Dangling symlinks count as existing. Targets must be absent.
- Validation runs fully before any write. Writes create missing parents and use mode "xb", so an existing file is never overwritten. OSErrors propagate unchanged.

Decisions and assumptions:
- Entries must be tuples, per "(name, data) tuples" in the spec. Lists are rejected.
- Only root and its descendants are checked; the spec's "below root" scope excludes root's own ancestors.
- The commit has no Co-Authored-By trailer: CLAUDE.md forbids Claude attribution, which overrides the attribution reminder.
- Test PermissionError propagation is skipped when running as root.

Known limitations (not in the spec, not handled):
- Case-insensitive filesystems (macOS default): a batch with 'A' and 'a' passes validation, and the second write then fails with FileExistsError after earlier files were written.
- A mid-write I/O error leaves partial output (no rollback), as the spec puts rollback out of scope.
- Assertions are sparse (one invariant in the write loop). Validation is explicit ValueError raises at the boundary, not assert-based, so the CLAUDE.md two-assert quota is not met on every function.
