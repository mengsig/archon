Added cursor pagination to inventory-api GET /items and updated inventory-client listItems to follow it. Both repos are committed (inventory-api d76e44a, inventory-client b08627c) with clean trees.

inventory-api:
- GET /items takes limit (digits only, 1..100, default 20) and cursor. Body is {"items": [...], "next_cursor": string|null}. Items are ordered by id.
- The cursor is a strict base64url encoding of the last id returned. Paging is keyset (id > last), so it is stable. Non-canonical or malformed cursors are rejected.
- Invalid limit or cursor returns 400 with {"error": "..."}.
- Two assertions guard the page bounds. Tests went from 3 to 8 and all pass (python3 -m unittest). README documents the change.

inventory-client:
- listItems requests the first page with no cursor, then passes each next_cursor back unchanged until it is null or absent. It throws on a page without an items array, a non-string cursor, or a repeated cursor.
- Tests went from 3 to 10 and all pass (npm test). README updated.
- Integration check: listItems through a Node transport that runs api_cli.py returns all 57 items in order.

Choices I made:
- Page size is the server default (20); the client does not send a limit.
- I did not bump the client's package.json version (1.4.0). listItems now pages internally, which may warrant a bump if you publish.
