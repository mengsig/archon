Multi-currency change done in both repos, each committed on its own. Tests pass: `cargo test` in ledger (7 integration tests), `python3 -m unittest` in reports (5 tests). I did not run `cargo clippy` or any other lint.

ledger (commit a1c3784):
- Lines take an optional 4th TSV column. Missing means USD. The header is `date,account,amount_cents,currency`, and every row carries the currency.
- `parse_line` returns a new `ParseError` enum with `Malformed` and `BadCurrency` variants. A bad currency code exits 2. Other malformed input still exits 1. The error text carries the line number.
- Code must be exactly three uppercase ASCII letters. Empty or lowercase codes are rejected.
- README updated.

reports (commit 6f866e8):
- Output is `account,currency,total_cents`, sorted by account then currency.
- Input without a `currency` column counts as USD. A bad code prints `error: line N: bad currency ...` to stderr and exits 2.
- Tests added for legacy CSV, per-currency totals, bad currency (including the line number), and empty currency. README updated.

Choices I made:
- Legacy input is detected from the header, not from empty cells. A row with an empty `currency` value in a file that has the column is an error, not USD.
- Commits use the repo's configured identity (mengsig) and include the Co-Authored-By line from the attribution reminder.

Caveat, noted in the reports README: `ledger` prints its header before it hits a bad line. When it exits 2 the pipeline still succeeds, and `reports` prints an empty total with exit 0. Callers need `set -o pipefail` or to check ledger's status. I did not change this, since the spec does not cover it.
