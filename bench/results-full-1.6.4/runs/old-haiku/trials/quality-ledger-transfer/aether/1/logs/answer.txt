`ledger.py` is implemented to `SPEC.md` and committed as `db77006` on `main`. All 22 tests pass, and the concurrency tests passed on five repeated runs.

**Implementation (`ledger.py`)**
- **Construction:** accepts only a dict. Account names must be non-empty strings. Balances must be built-in `int` in `[0, MAX_BALANCE]`, so booleans, floats and subclasses are rejected. The input is copied, so later changes to it don't affect the ledger.
- **`transfer`:** validates the amount first, then looks up both accounts (`KeyError` if either is unknown). It returns `False` on insufficient funds or destination overflow, leaving balances unchanged. A same-account transfer returns `True` iff the funds suffice, and never changes the balance.
- **`snapshot`:** returns a copy taken under the lock.
- **Thread safety:** one `threading.Lock` per ledger covers every operation. This makes transfers and snapshots linearizable and rules out deadlock between opposite transfers.
