The stale category price comes from the **listing cache path**. `Catalog.listing()` caches each category/page under a `listing:<category>:<page>` key and serves that cached snapshot until it expires ([catalog.js](/home/mengsig/.local/share/archon-bench/release-167-R4V9TB/r-lzwaa8jj/archon-bench/work/20261128T072020Z/35e9fae455a7f11cc81f6791/ask-cache-invalidation/src/catalog.js:22), [keys.js](/home/mengsig/.local/share/archon-bench/release-167-R4V9TB/r-lzwaa8jj/archon-bench/work/20261128T072020Z/35e9fae455a7f11cc81f6791/ask-cache-invalidation/src/keys.js:3)). Those entries have a 600-second TTL ([config.js](/home/mengsig/.local/share/archon-bench/release-167-R4V9TB/r-lzwaa8jj/archon-bench/work/20261128T072020Z/35e9fae455a7f11cc81f6791/ask-cache-invalidation/src/config.js:7)), so a price change can leave a listing stale for up to ten minutes after that entry was populated.

`updatePrice()` updates the store and deletes only the product’s cache key; it never invalidates the category listing ([pricing.js](/home/mengsig/.local/share/archon-bench/release-167-R4V9TB/r-lzwaa8jj/archon-bench/work/20261128T072020Z/35e9fae455a7f11cc81f6791/ask-cache-invalidation/src/pricing.js:10)). That’s why product pages update immediately while listings remain stale.

**Fix:** after a successful price update, invalidate every cached listing page for the product’s category. The current cache only supports deleting one exact key, so add a way to track or invalidate a category’s listing keys (or use category versioning) and cover all pages.
