Refactored the orders crate from String statuses to an OrderStatus enum and committed it as c64d513 on main. cargo test passes (3 existing integration tests plus 3 new unit tests in src/status.rs); clippy --all-targets is clean.

What changed:
- src/status.rs (new): OrderStatus {Pending, Paid, Shipped, Cancelled} deriving Debug, Clone, Copy, PartialEq, Eq, Hash; as_str; Display; FromStr with ParseStatusError (implements std::error::Error, message `unknown order status "<input>"`); can_transition_to encoding the four allowed edges.
- Order::status is now OrderStatus. pay, ship and cancel check can_transition_to, which is equivalent to the old checks. Their error messages are unchanged.
- src/lib.rs re-exports OrderStatus and ParseStatusError.
- report::from_line parses via FromStr and keeps the original `unknown status "<x>"` error text and field-check order.
- status_counts still returns Vec<(String, usize)> sorted by name. I keyed the BTreeMap on as_str rather than deriving Ord, because deriving Ord would sort by declaration order and change the report ordering.
- The status literals appear only in src/status.rs.
