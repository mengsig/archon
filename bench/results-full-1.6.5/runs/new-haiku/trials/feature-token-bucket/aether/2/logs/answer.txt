The rate limiter is implemented in `ratelimit.py` per `SPEC.md`, and committed as `4a83142` on `main`. All 16 tests pass (the 3 original ones plus 13 new edge-case tests I added to `test_ratelimit.py`).

**What's implemented**
- **`TokenBucket`**: starts full, refills continuously and is capped at `capacity`. `try_acquire` consumes only on success. `wait_time` returns the seconds until the request would succeed, without consuming tokens.
- **`KeyedLimiter`**: one bucket per key, kept in an `OrderedDict` for LRU order. Both `try_acquire` and `wait_time` count as a use. A new key beyond `max_keys` evicts the least recently used key, and an evicted key that returns starts full.
- **Errors**: invalid `capacity`, `refill_per_sec`, `max_keys` and request sizes raise `ValueError`. Validation runs before any state change, so a rejected call on an unseen key creates no bucket.
- **Clock regression**: the bucket tracks the latest time it has seen, and nothing changes until the clock passes it.
- Standard library only.

**Choices I made where the spec was silent**
- Parameter checks use `not x > 0`, so NaN is rejected as well as zero and negatives.
- Calling `wait_time` on an unseen key creates that key's bucket, since it counts as a use under the spec.
- I did not add a separate test-only clock or any other new public API.
