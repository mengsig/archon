All four tickets (TT-101 to TT-104) are implemented, each in its own commit on `main`. The suite runs 40 tests, all passing, with only the standard library.

| Ticket | Commit | What changed |
|---|---|---|
| TT-101 | `46dfa5b` | `parse_due` raises `InvalidDate` (a `ValueError` subclass) for impossible dates, unsupported forms and out-of-range offsets. The message contains the original text. |
| TT-102 | `01f57b5` | `to_csv` uses the `csv` module with CRLF line endings, so only fields containing comma, quote, CR or LF are quoted. |
| TT-103 | `826d591` | `search` parses the query into AND-ed terms. Quotes group phrases, `tag:` and `status:` filter on fields, and malformed queries raise `QueryError`. |
| TT-104 | `d8499ac` | `TaskStore.undo()` reverts the most recent successful add, complete or delete. Restored tasks keep their id, tags, due date and status. Ids are never reused. |

New tests are in `tests/test_dates.py`, `tests/test_export.py`, `tests/test_search.py` and `tests/test_store_undo.py`.

Choices I made where the tickets left room:
- **TT-101:** Digits are matched as `[0-9]`, so Unicode digits are rejected.
- **TT-103:** Field names and status values are case-insensitive. An empty value such as `tag:` raises `QueryError`. A quoted `"3:1"` is a phrase, not a field.
- **TT-104:** Completing a task that is already done is recorded, and undoing it leaves the task done. Literally, the ticket says undo "makes the task open again", which would wrongly reopen a task that was done before. `undo()` returns the affected task.
- **Commit trailers:** I added no `Co-Authored-By` line, because the project CLAUDE.md asks for no attribution and takes precedence over the attribution reminder. Commits use the repo's configured `mengsig` identity.

The working tree is clean and the `__pycache__` directories are removed.
