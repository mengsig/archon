**Root cause:** `listing(category, page)` caches a snapshot of each category page’s `{sku, name, priceCents}` under its own listing key. `updatePrice` updates the store and deletes only `product:<sku>`; it leaves every cached `listing:<category>:<page>` entry untouched. So the product page reloads the new price, while category pages keep serving the old snapshot. ([pricing.js](/home/mengsig/.local/share/archon-bench/release-167-R4V9TB/r-a7e9g5pr/archon-bench/work/20261128T072017Z/edf39508f599672806197dbe/.archon/data/orchestrator/repos/ask-cache-invalidation/src/pricing.js:10), [catalog.js](/home/mengsig/.local/share/archon-bench/release-167-R4V9TB/r-a7e9g5pr/archon-bench/work/20261128T072017Z/edf39508f599672806197dbe/.archon/data/orchestrator/repos/ask-cache-invalidation/src/catalog.js:22))

**Why about ten minutes:** listing entries have a 600-second TTL. The cache checks expiry only when a key is read, then drops the expired entry and rebuilds it. A listing cached just before the price change can therefore remain stale for nearly ten minutes. ([config.js](/home/mengsig/.local/share/archon-bench/release-167-R4V9TB/r-a7e9g5pr/archon-bench/work/20261128T072017Z/edf39508f599672806197dbe/.archon/data/orchestrator/repos/ask-cache-invalidation/src/config.js:7), [cache.js](/home/mengsig/.local/share/archon-bench/release-167-R4V9TB/r-a7e9g5pr/archon-bench/work/20261128T072017Z/edf39508f599672806197dbe/.archon/data/orchestrator/repos/ask-cache-invalidation/src/cache.js:10))

**Fix:** after a successful price update, invalidate the listing cache entries for that product’s category across all pages, as well as the product key. The current cache API only deletes individual keys, so add a way to invalidate a category’s listing entries (or use a per-category cache version/key that can be advanced). Reducing the TTL would only shorten the stale window; it would not make category prices update immediately.
