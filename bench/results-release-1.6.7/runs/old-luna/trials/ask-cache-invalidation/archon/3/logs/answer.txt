The category pages use a separate listing cache. [`Catalog.listing`](</home/mengsig/.local/share/archon-bench/release-167-R4V9TB/r-a7e9g5pr/archon-bench/work/20261128T072017Z/ccad9fa54603bf5132f32977/.archon/data/orchestrator/repos/ask-cache-invalidation/src/catalog.js:22>) caches each category/page’s rows, including `priceCents`. When a merchant changes a price, [`updatePrice`](</home/mengsig/.local/share/archon-bench/release-167-R4V9TB/r-a7e9g5pr/archon-bench/work/20261128T072017Z/ccad9fa54603bf5132f32977/.archon/data/orchestrator/repos/ask-cache-invalidation/src/pricing.js:10>) updates the store and evicts the product cache entry, but leaves those listing entries intact. That’s why the product page updates while category pages can remain stale.

The delay comes from the listing cache’s **600-second TTL** ([`config.js`](</home/mengsig/.local/share/archon-bench/release-167-R4V9TB/r-a7e9g5pr/archon-bench/work/20261128T072017Z/ccad9fa54603bf5132f32977/.archon/data/orchestrator/repos/ask-cache-invalidation/src/config.js:7>)). Its timer starts when a listing is cached, so a price change can leave it stale for up to ten minutes, depending on the entry’s age.

The fix is to evict all cached pages for the updated product’s category after the store update succeeds, or bump a category listing version so the next request rebuilds them. The current cache exposes exact-key deletion only, so it needs category-wide invalidation support ([`cache.js`](</home/mengsig/.local/share/archon-bench/release-167-R4V9TB/r-a7e9g5pr/archon-bench/work/20261128T072017Z/ccad9fa54603bf5132f32977/.archon/data/orchestrator/repos/ask-cache-invalidation/src/cache.js:24>)).
