**Critical — `src/tokens.js`, `verify`:** The signature check accepts any prefix of the expected HMAC. For example, a token ending in `.` has an empty signature, and every string starts with the empty string. An attacker can therefore supply a forged payload with a future `exp` and have it accepted. Even a one-character signature is accepted when it matches the HMAC’s first character. Require an exact, constant-time comparison of the full signature.

**Moderate — `src/tokens.js`, `verify`:** Malformed tokens can throw instead of returning `null`. For example, `abc.valid` reaches `JSON.parse` with invalid JSON; a missing or invalid `secret` can also make `createHmac` throw. If callers rely on `null` for invalid tokens, these inputs can turn routine verification failures into request errors. Catch parsing and crypto errors and return `null` for invalid inputs.
