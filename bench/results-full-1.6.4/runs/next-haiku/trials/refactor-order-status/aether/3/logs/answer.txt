Refactored the orders crate from String statuses to an OrderStatus enum and committed it as 2e42af9 on main. `cargo test` passes (3 integration tests, 3 new unit tests in src/status.rs); clippy with -D warnings and `cargo fmt --check` are clean.

What changed:
- src/status.rs (new): OrderStatus {Pending, Paid, Shipped, Cancelled} deriving Debug, Clone, Copy, PartialEq, Eq, Hash; as_str(); Display via f.pad (so width flags behave as they did for String); FromStr with Err = ParseStatusError; can_transition_to() encoding the four allowed edges. ParseStatusError implements Error, and its message names the rejected input.
- Order::status is now OrderStatus. pay, ship and cancel check can_transition_to, and their error messages are unchanged. is_open uses matches!.
- report::status_counts now returns Vec<(OrderStatus, usize)>, ordered by name via a BTreeMap keyed on as_str(), so the order matches the old output. from_line keeps the old "unknown status" message and check order.
- lib.rs re-exports OrderStatus and ParseStatusError, and declares pub mod status.
- tests/orders.rs compares against enum variants. Literal status names remain only in src/status.rs; the CSV line and error-message expectations stay as literal text because they are observable output.
