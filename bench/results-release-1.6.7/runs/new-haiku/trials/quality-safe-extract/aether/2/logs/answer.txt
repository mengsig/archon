`extract(entries, root)` is implemented in `safe_extract.py` per `SPEC.md`, using only the standard library. The 34 tests pass (`python3 -m unittest`), and the work is committed as `c5d1a75` on `main` under mengsig.

**What it does:** the whole batch is validated before anything is written. The checks cover:
- **Batch type:** only a `list` is accepted. Tuples, generators and iterators are rejected without being consumed.
- **Root:** must be a `str` or `Path` naming an existing real directory, not a symlink.
- **Entries:** each must be a 2-tuple with a `str` name and `bytes` data.
- **Names:** nonempty, relative, no leading `/`, backslash, colon or NUL, and no empty, `.` or `..` components. Names are not normalized or decoded.
- **Batch conflicts:** duplicates, and file/directory collisions in either order.
- **On disk:** no symlinks below root (dangling ones included), ancestors must be directories, and the target must be absent.

Files are created with exclusive mode, so existing content is never overwritten. Empty batches return `[]` after root validation. Names are returned in input order.

**Choices where the spec was silent:**
- Lists of length 2 are rejected as entries; only tuples are accepted.
- Names that can't be UTF-8 encoded, such as lone surrogates, are rejected up front.
- An empty-string root is rejected.
- A root below a file is a `ValueError`, not an `OSError`.
- Unexpected OS errors such as `PermissionError` propagate unchanged.

**Not covered:** a failure partway through writing leaves a partial batch, which the spec places out of scope. Case-insensitive filesystems are not handled specially.
