The rate limiter is implemented in `ratelimit.py` per `SPEC.md` and committed as `ac80b11` on `main`. All 16 tests pass (`python3 -m unittest test_ratelimit`).

- **Implementation:** `TokenBucket` and `KeyedLimiter` use only the standard library. Both reject invalid capacity, refill rate and `max_keys`. `KeyedLimiter` evicts the least recently used key when full.
- **Tests:** I added 13 tests to `test_ratelimit.py` for the spec's error and edge cases: validation, failed acquires consuming nothing, refill capping, fractional tokens, `wait_time` not consuming, clock going backwards, and LRU eviction.

Choices I made where the spec was silent:
- **NaN is rejected** for capacity, refill rate and `n`. The spec's `<= 0` checks would let NaN through.
- **Infinite capacity or refill is allowed**, since the spec doesn't forbid it.
- **Bad `n` is rejected before a key is created**, so an invalid request cannot evict another key.
- **No `Co-Authored-By` trailer**, because CLAUDE.md forbids Claude attribution in commits.

Known limitation: `wait_time` returns exact float seconds, so at the boundary floating-point rounding can make `try_acquire` fail by a tiny epsilon.

An untracked `__pycache__/` directory from the test run is left uncommitted.
