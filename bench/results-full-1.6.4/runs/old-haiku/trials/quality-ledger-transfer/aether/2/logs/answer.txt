I implemented `ledger.py` per `SPEC.md` and committed it as `55ff328` on `main`, under the repo's configured git user. All 24 tests in `test_ledger.py` pass on three consecutive runs, using only the standard library.

- **Construction:** a non-dict input, an invalid name, or an invalid balance raises `ValueError`. `bool` is rejected as a balance. The input dict is copied.
- **`transfer`:** the amount is validated first, then both accounts are looked up (`KeyError` if unknown). The checks and both writes run under one `threading.Lock` per ledger, so transfers are linearizable and opposite transfers cannot deadlock.
- **Failures:** insufficient funds and destination overflow return `False` and change nothing. A self-transfer returns whether the account has enough funds and never changes it.
- **`snapshot`:** returns a copy taken under the lock.

Choices the spec did not settle:
- A non-string account name passed to `transfer` raises `KeyError`, not `TypeError`, so unhashable values like lists are handled.
- Amounts and balances must be exactly `int`, so int subclasses and `bool` are rejected.
- I used explicit `ValueError` checks rather than `assert`, since the spec requires `ValueError` for bad input.
