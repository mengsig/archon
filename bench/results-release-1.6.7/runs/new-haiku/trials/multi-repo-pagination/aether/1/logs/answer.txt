**API (`inventory-api/api.py`)**
- `limit` accepts only plain digits from 1 to 100; default 20. Values like `" 5"`, `"+5"`, `"2.5"` and `"0"` get 400.
- `next_cursor` is the URL-safe base64 of the last returned item's id. Clients see it as an opaque string. A cursor is valid only if it decodes to digits and re-encodes to the same string. Anything else, including an oversized one, gets 400 with `{"error": "cursor is invalid"}`.
- Each page is the items with `id` greater than the cursor's id, so pages stay stable if items are added later.
- `next_cursor` is `null` when no items remain after the page. A page that exactly uses up the data also returns `null`.

**Client (`inventory-client/client.js`)**
- `listItems` makes the first request with no query, then passes `next_cursor` back unchanged until it is `null` or absent.
- It rejects if a page fails, and also if `next_cursor` is the same as the cursor just sent. That stops a misbehaving server from looping forever.
