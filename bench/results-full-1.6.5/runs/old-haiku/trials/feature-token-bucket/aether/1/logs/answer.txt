The rate limiter is implemented in `ratelimit.py` and committed as `74ffc01` on `main`. All 12 tests pass.

- **`TokenBucket`**: rejects a capacity or refill rate that is not greater than 0. It starts full and refills continuously, capped at capacity. `try_acquire` and `wait_time` raise `ValueError` unless `0 < n <= capacity`, and a failed `try_acquire` consumes nothing. If the clock goes backwards, nothing is added until it passes the latest time seen.
- **`KeyedLimiter`**: rejects `max_keys < 1` as well as bad capacity or rate. It keeps one bucket per key in an `OrderedDict`. Both `try_acquire` and `wait_time` count as a use. When a new key would exceed `max_keys`, the least recently used key is evicted, and an evicted key that returns starts full. An invalid `n` raises before any key is created.
- **Tests**: I added 9 edge-case tests to `test_ratelimit.py` covering the spec's error and eviction cases. The file's original 3 tests are unchanged.

Assumptions:
- `wait_time` on a brand-new key creates that key, since the spec says it counts as a use.
- `n`, `capacity` and `refill_per_sec` are checked only with comparisons. I did not add type checks.
