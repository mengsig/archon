Implementation:
- Construction validates a dict of nonempty str names to built-in int balances in [0, MAX_BALANCE]; it copies the input, so later mutation of the caller's dict doesn't reach the ledger. Booleans are rejected via `type(x) is int`.
- transfer validates the amount first (ValueError), then both accounts (KeyError), then applies the rules: insufficient funds and destination overflow return False with no change; same-account returns True iff funds suffice and never mutates.
- snapshot returns a copy.
- A single threading.Lock guards every transfer and snapshot. That makes each transfer atomic, keeps snapshots from seeing partial transfers, and rules out deadlock since only one lock is held.

Tests: kept the two original tests, and added coverage for construction validation and boundaries, copy semantics, amount and account error ordering, overflow boundaries, same-account behavior, and concurrency (total preserved under contention, opposite transfers finishing, snapshot totals never torn). The concurrency tests use thread joins with a timeout and no random inputs or wall-clock assertions.
