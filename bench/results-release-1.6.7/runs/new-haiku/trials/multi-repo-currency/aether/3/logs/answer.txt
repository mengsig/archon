**ledger**
- Lines take an optional fourth column, the ISO 4217 code. A missing column means `USD`.
- The header is `date,account,amount_cents,currency`, and every row carries its currency.
- A malformed code prints `line N: bad currency ...` to stderr and exits 2. Other input errors still exit 1.
- `parse_line` now returns a `LineError` enum so the exit status can be chosen per error. This changes the library's public signature.
- A new `tests/cli.rs` checks the exit codes through the real binary.

**reports**
- Totals are keyed by account and currency. Output is `account,currency,total_cents`, sorted by account, then currency.
- CSV without a `currency` column counts as `USD`.
- A malformed or missing currency prints `error: line N: ...` to stderr and exits 2.

I ran the two tools together on a small sample. The totals came out as expected, and a lowercase code made `ledger` exit 2 with the line named.

Assumptions you may want to check:
- An empty fourth column (a trailing tab) counts as a malformed code and exits 2. I did not treat it as "missing".
- Currency values are trimmed like the other fields.
- The commits carry no Co-Authored-By trailer. The project CLAUDE.md forbids attribution, and I followed it over the session reminder.
