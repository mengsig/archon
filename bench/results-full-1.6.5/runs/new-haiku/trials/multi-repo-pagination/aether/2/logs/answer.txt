**Commits**

- `inventory-client` `db371d8`: "Follow next_cursor in listItems"

**API (`inventory-api/api.py`)**
- `limit` must be ASCII digits in 1..100; absent means 20. Anything else returns 400.
- `cursor` is URL-safe base64 of the last id on the page. Items after that id are returned, and `next_cursor` is `null` when nothing remains. Undecodable or non-numeric cursors return 400.
- Items are sorted once at import time, not on every request.

**Client (`inventory-client/client.js`)**
- `listItems` sends no query on the first request, then passes `next_cursor` back unchanged until it is `null` or absent.
- It throws if the server repeats a cursor, so a buggy server can't loop forever. That is a choice I made beyond the brief.

- Client: 7 pass. New tests cover multi-page order, the first request having no cursor, an absent `next_cursor`, repeated cursors, and 400 responses.
